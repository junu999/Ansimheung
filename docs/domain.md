# 도메인 규칙 — 정책(P) · 상수(C) · 검증(V) · 알고리즘

> 노션 "상수(C)·검증 규칙(V)", "위험도 산정식", "안전 경로 알고리즘", "개인정보·데이터 정책"(11/08 확정본)을 저장소로 옮긴 것.
> **값의 실제 위치는 코드**(`application.yml` `ansimheung.*`, `common/type/*` enum)이고, 이 문서는 설명용이다. 값을 바꾸면 코드·이 문서·노션을 같이 고친다.

## 1. 용어

| 한글 | 코드 | 뜻 |
|---|---|---|
| 위험 지점 | `Hazard` | 지도 마커 1개. 같은 위치(20m)·같은 유형 제보가 묶인 단위. 점수·상태는 여기에 붙음 |
| 제보 | `Report` | 주민 한 명이 올린 기록 1건. 반드시 하나의 Hazard에 속함 |
| 공감 | `Empathy` | "나도 겪었어요". 1인 1지점 1회 |
| 위험점수 | `riskScore` / `baseScore` | baseScore = W×R×E×S (DB 저장), riskScore = baseScore×T (조회 시) |
| 도보 그래프 | `Node`, `Edge` | 교차로 = 노드, 길 토막 = 구간 |
| 구간 위험도 | `edgeRisk` | 그 구간에 배정된 위험 지점 점수 합 |
| 경로 비용 | `cost` | 길이 + λ × edgeRisk |
| 시드 | `seed` | 시연용 예시 데이터 (local/dev 프로필만) |

서버가 최종 검증(`@Valid`), 프론트는 같은 규칙으로 미리 안내. 실패 시 `VALIDATION` + `fields`에 아래 메시지 그대로.

| ID | 대상 | 규칙 | 메시지 |
|---|---|---|---|
| V-01 | email | 필수, 이메일 형식, 최대 100자, trim + 소문자 저장 | 이메일 형식이 아니에요 |
| V-02 | password | 8~64자, 영문·숫자 각 1개 이상 | 비밀번호는 영문과 숫자를 포함해 8자 이상이어야 해요 |

## 5. 처리상태 전이

```
RECEIVED(접수) ──▶ CHECKING(확인중) ──▶ RESOLVED(개선완료)
      │                  │
      └──────▶ REJECTED(반려) ◀──┘
```
- 코드: `HazardStatus.allowedNext()` / `canTransitionTo()`. 그 외 전이는 409 `STATE_CONFLICT`.
- 숨김은 상태가 아니라 `hazards.hidden` 플래그(사유 필수, 이력에 기록).
- 상태가 바뀌면: `status_histories` 저장 → 점수 재계산 → (선택) 제보자 알림.

## 6. 위험점수

```
riskScore = W(유형) × R(최근성) × E(공감) × S(처리) × T(시간대)     범위 약 0.18 ~ 9.0
```
- DB `hazards.base_score` = **W×R×E×S** 만 저장. **T는 조회할 때 곱한다** (같은 지점도 등교·하교 시간에 점수가 다름).
- 재계산 시점: 제보 등록·공감 변경·상태 변경 직후 (+ 매일 03:00 R 갱신 — 이번 제출 범위 제외 #28).
- 반려 지점은 계산 제외(0), 지도에서도 빠짐.

### 테스트 기대값 (그대로 JUnit에 사용)
정왕초 후문 앞 불법주정차, 마지막 활동 10일 전, 공감 3, 접수, 제보 시간대 등교

| 항목 | 값 | 계산 |
|---|---|---|
| W | 1.8 | 불법주정차 |
| R | 1.39 | 1.5 − 10/90 |
| E | 1.60 | 1 + log10(4) |
| S | 1.0 | 접수 |
| baseScore | **4.0** | 1.8 × 1.39 × 1.60 × 1.0 |
| 등교 시간 조회 | **6.0** | 4.0 × 1.5 |
| 하교 시간 조회 | **4.0** | 4.0 × 1.0 |
| 개선완료 후 등교 조회 | **1.8** | 4.0 × 0.3 × 1.5 |

(소수 첫째 자리 반올림 비교. 내부 값은 반올림하지 않는다.)

## 7. 안전 경로

1. 위험 지점 → **가장 가까운 구간 1개**에 배정 (거리 ≤ 25m, C-09). PostGIS `ORDER BY geom <-> 위치 LIMIT 1`. 넘으면 `edge_id = null`(지도엔 보이지만 경로엔 영향 없음).
   - 반경 합산 금지: 교차로 모퉁이 위험 하나가 구간 4개에 잡혀 중복 계산됨.
2. `edgeRisk(e)` = 구간 e에 배정된 지점들의 **시간대 반영 점수** 합.
3. `cost(e) = length_m(e) + λ × edgeRisk(e)` → Dijkstra.
4. `POST /api/routes`: 범위 확인(`OUT_OF_AREA`) → 출발지를 가장 가까운 노드에 스냅(50m 초과 `FAR_FROM_ROAD`) → 목적지 = 정왕초 정문 노드(고정) → λ = 0/20/60으로 **Dijkstra 3회** → 경로마다 거리·예상 시간·위험 노출(edgeRisk 합)·지나는 지점 ID → **출발지 좌표 폐기**.
5. 사전 계산·캐시 없음 (노드 100~200개, 1회 1ms 미만). 그래프는 서버 시작 시 메모리 적재, 비어 있으면 `NO_GRAPH`(503), 경로 없으면 `NO_ROUTE`(404).

### 테스트 기대값 (노드 5개 그래프)
A 골목 200m·위험 15 / B 큰길 350m·위험 2

| λ | A 비용 | B 비용 | 선택 |
|---|---|---|---|
| 0 | 200 | 350 | A |
| 20 | 200+15×20 = 500 | 350+2×20 = 390 | B |
| 60 | 1100 | 470 | B |

### 검증 지표 (발표자료 근거)
- 안전 경로 위험 노출이 최단 대비 30% 이상 감소, 거리 증가 30% 이내 (시드 30건 · 출발지 여러 곳 비교)
- 경로 응답 1초 이내
- ⚠️ 우리 시드로 우리 알고리즘을 잰 것 → "알고리즘 동작 검증"이라고만 표현 (실제 사고 감소 효과 주장 금지)

## 8. 화면 표시 규칙 (프론트)

- 마커 색: 서버 `level` 그대로 (`HIGH` 빨강 · `MEDIUM` 주황 · `RESOLVED` 회색).
- 위험점수 막대: 서버 점수(최대 9.0)를 100점 만점으로 환산 (`mappers.js` `toDisplayScore`). 경로 위험 노출도 같은 환산.
- 제보 등록 화면은 별도 제목 없이 선택 설명 `description`(최대 200자)을 보낸다 (#17, V-09). 기존 제목+설명 형식의 제보는 상세에서 첫 줄과 나머지를 나누어 표시한다.
- 시드 데이터 화면에는 "시연용 예시 데이터" 표시.
